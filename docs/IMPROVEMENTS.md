# What was added or changed compared with the original project

The original repository contained a Node.js backend, a basic Jenkinsfile (the real pipeline lived in an external
shared library that was not included), a minimal Helm chart and Terraform that relied on third-party modules and
hard-coded values. Its README also described components (monitoring, React front-end, scanners, setup scripts)
that had no implementation in the repo. This version implements them.

## Application
| Before | After |
|--------|-------|
| SQL built with string concatenation (injection risk) | Parameterised queries via a `mysql2` pool |
| No validation, `if (success = 200)` bug, broken `/transaction/id` routes reading the body | Input validation, proper REST routes (`/transaction/:id`), correct status codes |
| Credentials in `DbConfig.js` | Environment variables only; app refuses to start in production without `DB_PWD` |
| No readiness check, no metrics, no graceful shutdown | `/health`, `/ready`, `/metrics` (Prometheus), SIGTERM handling, JSON logs |
| No tests | 25 Jest/Supertest tests |
| No front-end in the repo | React (Vite) app served by unprivileged nginx with `/api` reverse proxy |
| Single-stage Dockerfile | Multi-stage, non-root, `tini`, healthcheck, `.dockerignore` |

## Infrastructure (Terraform)
* No dependency on a third-party author's modules, AMI or domain: uses official registry modules and native resources.
* Remote state bootstrap stack (versioned, encrypted, TLS-only S3 bucket) with native state locking; no hard-coded bucket.
* DB passwords generated by Terraform and stored in Secrets Manager (originally a plain-text password in code and README).
* RDS: MySQL 8.4 (8.0 is past standard support), encrypted gp3 storage, backups, CloudWatch logs, private.
* EKS: current Kubernetes version, AL2023 nodes, IMDSv2, IRSA roles for the Load Balancer Controller and EBS CSI driver
  (replaces manual `eksctl` steps and the broad `AmazonElasticFileSystemFullAccess` / `ElasticLoadBalancingFullAccess` node policies),
  network-policy support in the VPC CNI, EKS access entry for the bastion.
* Bastion: Amazon Linux 2023, SSM Session Manager, SSH closed unless CIDRs are provided, scoped IAM policy.
* ALB: HTTP→HTTPS redirect, TLS 1.3 policy, `/healthz` health check, Route 53 alias, target group ARN exported.
* ECR: lifecycle policy added; ACM/Route 53 use data sources instead of copied zone IDs.

## Delivery
* Complete declarative `Jenkinsfile` (tests → SonarQube gate → Trivy → build → image scan → ECR → GitOps promotion) instead of a shared-library stub.
* ArgoCD app-of-apps with automated sync and self-heal; Jenkins commits the image tag, never touches the cluster.
* Helm chart for both tiers with HPA, PDB, topology spread, probes, hardened security contexts, NetworkPolicies, TargetGroupBinding.
* GitHub Actions workflow (tests, build, `helm lint` + kubeconform, `terraform validate`, Trivy) and Dependabot.

## Observability
* kube-prometheus-stack values, ServiceMonitor, 5 alert rules and a Grafana dashboard; local Compose profile with the same dashboard.

## Operations & docs
* `scripts/` for state-aware Terraform runs, cluster bootstrap, DB init and secret creation.
* The missing `jenkins.sh` / `jenkins-agent.sh` referenced by the old README, Jenkins setup guide, runbook, architecture document.
